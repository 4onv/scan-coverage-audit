# Scan Coverage Audit

A scanner can report zero findings after checking only part of your repository. Scan Coverage Audit compares a Git file inventory with ESLint, Semgrep, or custom reports and lists every expected file that was skipped, failed, or never appeared.

[![CI](https://github.com/4onv/scan-coverage-audit/actions/workflows/ci.yml/badge.svg)](https://github.com/4onv/scan-coverage-audit/actions/workflows/ci.yml)

## Try it

Download the `.tgz` archive and check its SHA-256 digest against `SHA256SUMS`. Run this command in the download directory with Node.js 22 or later. [Release downloads](https://github.com/4onv/scan-coverage-audit/releases/tag/v0.1.0)

```sh
npm --prefix . exec --offline --yes --package=./4onv-scan-coverage-audit-0.1.0.tgz -- scan-coverage-audit demo
```

```text
Synthetic demo · scanner findings: 0

FAIL  1/4 expected files scanned
      1 missing · 1 skipped · 1 errored · 0 scan-wide errors
  SKIPPED "src/coupons.js"
  MISSING "src/returns.js"
  ERROR   "src/tax.js"
```

The demo uses synthetic records and exits 0 when it runs successfully. For an installed command, run `npm install --global ./4onv-scan-coverage-audit-0.1.0.tgz`. The package has no dependencies and can be installed offline. From source, run `node bin/scan-coverage-audit.js demo`.

## Check your scanner

Run the scanner and generate the inventory from the same clean checkout. Git is required for `plan`. Keep scanner exit codes in CI as well, since the audit covers file coverage and a fully scanned project can still have findings.

```sh
scan-coverage-audit plan --ext .js --under src > inventory.json
npx eslint src --format json --output-file eslint.json
scan-coverage-audit check inventory.json --eslint eslint.json --report-root "$PWD"
```

The ESLint example assumes ESLint is installed and configured in the project. On PowerShell pass `--report-root $PWD.Path`. For Semgrep, run `semgrep scan --config path/to/rules.yml --json --output semgrep.json` from the repository root and pass `--semgrep semgrep.json`. Supply the original checkout path with `--report-root` if a report contains absolute paths. Windows absolute paths can be matched on Linux using the saved Windows checkout path.

`plan` defaults to `HEAD` and also accepts `--ref <commit-or-ref>` and `-C <repository>`. Repeat `--ext` for case-sensitive filename suffixes and `--under` for literal directory prefixes. With both filters, a file must match a suffix and a directory. Choose the expected scope independently of the scanner. Otherwise its own exclusions can vanish from the comparison.

Pass multiple reports of the same scanner and configuration with repeated flags to combine shards. An error on an expected file takes precedence over a later success. A scanned record takes precedence over a skip. Use separate audits when every scanner or ruleset must cover every file.

- **0** means every expected file has a scanned record and no scan-wide errors were reported.
- **1** means missing, skipped, or errored expected files, scan-wide errors, or extra records with `--fail-extra`.
- **2** means invalid input or an audit error.

Use `--json` for all gaps and extra paths. Extra paths are informational unless you pass `--fail-extra`. Records outside the supplied checkout root are counted without printing their absolute paths.

## Add another scanner

Export a version 1 receipt with repo-relative paths. A scanner should emit a `scanned` record only when it completes the file, even if it found nothing. Use `error` for failed files and `globalErrors` for failures that have no file.

```json
{
  "version": 1,
  "files": [
    {"path": "src/checkout.js", "status": "scanned"},
    {"path": "src/coupons.js", "status": "skipped"},
    {"path": "src/tax.js", "status": "error"}
  ],
  "globalErrors": 0
}
```

Pass the file as `--receipt report.json`. Findings-only formats cannot account for clean files unless the scanner also exports positive coverage evidence.

## Scope and limits

The inventory includes tracked regular files at a commit. It excludes uncommitted additions, symlinks, and submodule contents. Paths are UTF-8, case-sensitive, and use forward slashes. Plan and report files must be at most 32 MiB each. Up to 150,000 expected files and 600,000 report rows are supported.

The audit checks file-level declarations in reports you trust. It cannot prove which bytes, lines, or rules a scanner ran. Keep the reports tied to the same checkout and scanner run. Semgrep can report per-rule skips within a scanned file. ESLint parsing errors and its standard ignored-file placeholders are treated as coverage gaps, while ordinary lint findings count as evidence the file was checked.

Run `npm test` and `npm run demo` from source. CI also checks a report generated by ESLint 10.15.0. [November 13 research and comparisons](docs/research-2026-11-13.md)
